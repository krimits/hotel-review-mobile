# HostPulse / Hotel Pulse — Mobile Guest Care & Operations (V2)

> **Έκδοση 2 (HW2):** Προσθήκη εξαγωγής αναφορών απόδοσης & κριτικών σε **PDF και Excel (`.xlsx`)** με διαμοιρασμό ομάδας (στο 1-click Web Mockup `index.html`) + ενσωμάτωση της **native Android εφαρμογής** στον φάκελο [`android-app/`](android-app/README.md).

## Τι άλλαξε στη Version 2 (HW2) βάσει feedback αξιολογητών

Κατά τη διαδικασία αξιολόγησης (HW2), οι reviewers επαίνεσαν την οργάνωση, την ευχρηστία, τη συγκέντρωση κριτικών σε ένα σημείο, τον εντοπισμό επαναλαμβανόμενων προβλημάτων και το σύστημα συστάσεων ενεργειών βάσει σοβαρότητας και συχνότητας, και πρότειναν ως βασική βελτίωση:

> *«Δυνατότητα εξαγωγής των στατιστικών και των κριτικών σε μια αναφορά PDF ή Excel, ώστε ο υπεύθυνος του ξενοδοχείου να μπορεί να παρακολουθεί την απόδοση και να μοιράζεται τα αποτελέσματα με την ομάδα του.»*

Με βάση αυτή την παρατήρηση, στη **Version 2 (v0.4)** υλοποιήθηκαν:

1. **Στούντιο Εξαγωγής Αναφορών PDF & Excel στο Web Mockup (`index.html`):**
   - Προσβάσιμο από την αρχική οθόνη («Σήμερα»), τις «Κριτικές», τα «Μοτίβα» και το «Προφίλ».
   - Φίλτρα ανά κατάλυμα, χρονική περίοδο (7/14/30/60 ημέρες ή όλες), πηγή, συναίσθημα, εκκρεμή περιστατικά και συμπερίληψη προτεραιοποιημένων ενεργειών.
   - **Εξαγωγή πραγματικού αρχείου Excel (`.xlsx`) 3 φύλλων** (`Συνοπτικά KPIs`, `Μοτίβα & Ενέργειες`, `Αναλυτικές Κριτικές`) 100% client-side χωρίς εξωτερικές βιβλιοθήκες.
   - **Εξαγωγή εκτυπώσιμης αναφοράς PDF (A4)** με KPIs, κατανομή συναισθήματος, επαναλαμβανόμενα μοτίβα, προτεραιοποιημένες ενέργειες (σοβαρότητα × συχνότητα) και αναλυτικό πίνακα κριτικών.
   - **Ζωντανή προεπισκόπηση** PDF & Excel μέσα στην εφαρμογή και **διαμοιρασμός / αντιγραφή επιτελικής σύνοψης** για την ομάδα.
   - **Πλήρης διατήρηση των λειτουργιών V1:** σύστημα συστάσεων ενεργειών, ημερήσιο πλάνο με χρόνο/προϋπολογισμό, ανθρώπινη επιβεβαίωση, ανάθεση & παρακολούθηση εργασιών, οθόνη «Μοτίβα» και 1-click offline εκτέλεση.
2. **Native Android App (`android-app/`):**
   - Ενσωμάτωση της native Android υλοποίησης (**Hotel Pulse** — Kotlin, Jetpack Compose, Material 3, Firebase Auth/Firestore, Firebase AI Logic) με native A4 PDF renderer (`PdfReportGenerator.kt`), 3-sheet `.xlsx` generator (`ExcelReportGenerator.kt`), αποθήκευση SAF & Android Share Sheet (`ReportShareHelper.kt`).
   - Δες [`android-app/README.md`](android-app/README.md) για οδηγίες εκτέλεσης σε Android Studio και προεπισκόπηση στο Google AI Studio.

## Επισκόπηση Web Mockup (V1 → V2)

Διαδραστικό πρωτότυπο εφαρμογής κινητού για την **1η φάση της εργασίας**.
Ο υπεύθυνος λειτουργίας ξενοδοχείου ή αλυσίδας συγκεντρώνει κριτικές από πολλές
πηγές, εντοπίζει εκκρεμή και επαναλαμβανόμενα προβλήματα και συντονίζει την
αντιμετώπισή τους. Η εφαρμογή σχεδιάζεται ως το mobile περιβάλλον εργασίας πάνω
από το [hotel-review-nlp](https://github.com/krimits/hotel-review-nlp).

**Κεντρική ροή: πολλές πηγές → συνολικό συναίσθημα και επιμέρους θέματα →
ανθρώπινη επιβεβαίωση → ανάθεση → επίλυση → έλεγχος επαναλήψεων.**

**Κατάσταση: λειτουργικό mockup, χωρίς backend και χωρίς συνδεδεμένο AI μοντέλο.**
Οι αναλύσεις προσομοιώνονται με λεξικά και κανόνες στον browser. Οι απαντήσεις,
οι αναθέσεις και οι ειδοποιήσεις του demo δεν αποστέλλονται σε πραγματικούς
επισκέπτες ή εργαζομένους.

## Εκτέλεση

Άνοιξε το **`index.html`** με διπλό κλικ σε σύγχρονο Chrome, Edge, Firefox ή Safari.
Για χρήση του mock δεν απαιτούνται εγκατάσταση, Node.js, API key ή σύνδεση στο Internet.
Σε υπολογιστή εμφανίζεται σε πλαίσιο κινητού και σε μικρή οθόνη καταλαμβάνει
τον διαθέσιμο χώρο.

Στο πρώτο άνοιγμα εμφανίζεται ένας **οδηγός τεσσάρων βημάτων**: τι κάνει η
εφαρμογή, πώς διαβάζει τις κριτικές, πού είναι οι συστάσεις και τι αποφασίζει
ο χρήστης. Κλείνει με «Παράλειψη», Esc ή «Δες τις προτάσεις» και δεν ξαναβγαίνει
μόνος του. Ανοίγει ξανά από το **«?»** στην κορυφή ή από το Προφίλ. Η ένδειξη ότι
προβλήθηκε αποθηκεύεται χωριστά (`hostpulse.welcome.v1`) και δεν αλλάζει τα
δεδομένα του demo.

Για πιο σταθερή τοπική αποθήκευση, προαιρετικά:

```bash
python -m http.server 8000
```

Άνοιξε `http://localhost:8000`. Η σελίδα χρησιμοποιεί `localStorage` με κλειδί
`hostpulse.mock.v2`. Στο `file://` η συμπεριφορά αποθήκευσης εξαρτάται από τον
browser. Αν η αποθήκευση δεν επιτρέπεται, εμφανίζεται ενημέρωση και οι ροές
συνεχίζουν στη μνήμη μέχρι να κλείσει η σελίδα.

## Δοκιμές

Χρειάζεται Node.js όπως ορίζει το `package.json` (22.22+, 24.15+ ή 26+) και μία εγκατάσταση των εργαλείων:

```bash
npm ci
npm test            # λογική: ανάλυση, συστάσεις, πλάνο, αναθέσεις, αποθηκευμένη κατάσταση
npm run test:dom    # σελίδα σε jsdom: οδηγός πρώτης χρήσης, πλοήγηση, αποθήκευση
npm run test:ui     # πραγματικός browser σε μέγεθος κινητού: από τον οδηγό ως την ολοκλήρωση εργασίας
```

Το `test:ui` χρησιμοποιεί εγκατεστημένο Edge ή Chrome. Αν δεν υπάρχει, τρέξε
πρώτα `npx playwright install chromium`. Τα screenshots γράφονται στο
`test-results/`, που δεν μπαίνει στο git. Τα τεστ ελέγχουν τη συμπεριφορά του
mockup. Δεν μετρούν την ακρίβεια της ανάλυσης.

## Ιδέα, χρήστης και διαφοροποίηση

Το HostPulse διερευνά μια εναλλακτική προσέγγιση στην κατηγορία εργαλείων
διαχείρισης φήμης και εμπειρίας επισκεπτών, στην οποία ανήκει το **Reviewpro**.
Η βασική ιδέα της ανάλυσης κριτικών και της ανάθεσης περιστατικών ήδη υπάρχει.
Δεν ισχυριζόμαστε ότι το πρωτότυπο είναι το πρώτο τέτοιο προϊόν ή ότι έχει
την πληρότητα ενός εμπορικού συστήματος.

Η ειδικότερη σχεδιαστική υπόθεση είναι ένα **mobile κέντρο επιχειρησιακής
ανταπόκρισης για ξενοδόχους**, που συνδέει τα στοιχεία της ανάλυσης με πράξεις:

- Κάθε πρόταση συνδέεται με συγκεκριμένη κριτική και ακριβές απόσπασμα.
- Ένα ενιαίο inbox εμφανίζει προσομοιωμένες πηγές Booking.com, Tripadvisor,
  Google και εσωτερικής φόρμας, με φίλτρα πηγής, θέματος και καταλύματος.
- Η οθόνη «Μοτίβα» εντοπίζει επαναλαμβανόμενα θέματα σε ένα ή περισσότερα
  καταλύματα και οδηγεί στα συγκεκριμένα αποσπάσματα που τα στηρίζουν.
- Διακρίνονται εκκρεμή περιστατικά, ήδη λυμένα ζητήματα και επιθυμίες/υποθέσεις.
- Ένα συνολικά θετικό σχόλιο μπορεί να διατηρεί αρνητικό επιμέρους θέμα.
- Ο υπεύθυνος επιβεβαιώνει την ανάλυση πριν μπορέσει να εγκρίνει ανάθεση.
- Προαιρετικά, ο χρήστης περιορίζει το ημερήσιο πλάνο με χρόνο και προϋπολογισμό.

Αυτή η στόχευση χρειάζεται περαιτέρω έρευνα ανταγωνισμού και αξιολόγηση με
πραγματικούς χρήστες. Επειδή η εκφώνηση ζητά πρωτοτυπία, η παρουσίαση πρέπει
να εξηγεί τη συγκεκριμένη στόχευση και να αναγνωρίζει τα υπάρχοντα προϊόντα.
Δεν χρησιμοποιούνται εμπορικά assets, λογότυπα ή κώδικας του Reviewpro.

## Οθόνες και λειτουργικές ροές

| Οθόνη         | Τι μπορεί να κάνει ο χρήστης                                                                                                                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Σήμερα**    | Βλέπει μέση βαθμολογία, πραγματικά πλήθη από τα δείγματα, τάση οκτώ εβδομάδων και εκκρεμή περιστατικά. Πατά συγκεκριμένη κριτική ή δείκτη για να ανοίξει το σωστό στοιχείο/φίλτρο.                                           |
| **Κριτικές**  | Αναζητά χωρίς διάκριση τόνων, φιλτράρει συναίσθημα, αρμόδιο τμήμα εκκρεμούς ζητήματος και κατάσταση. Ανοίγει λεπτομέρειες, βλέπει αποσπάσματα, εγκρίνει ενέργεια και αποθηκεύει απάντηση demo.                               |
| **Ενέργειες** | Ρυθμίζει χρόνο, χρήματα και βάρη προτεραιοτήτων. Βλέπει πλάνο έως τριών παρεμβάσεων και άλλες προτάσεις. Εγκρίνει ανάθεση και μετακινεί εργασία από «Ανατέθηκε» σε «Σε εξέλιξη» και «Ολοκληρώθηκε».                          |
| **Δοκιμή**    | Αναλύει ελληνικό ή αγγλικό κείμενο με τοπικούς κανόνες. Διαθέτει παραδείγματα εκκρεμούς, λυμένου, επιθυμίας και αγγλικού κειμένου. Μπορεί να εισαγάγει νέα κριτική δείγματος στο κατάλυμα και με τη βαθμολογία που επιλέγει. |
| **Προφίλ**    | Βλέπει στοιχεία του σεναρίου, αλλάζει αποθηκευμένες προτιμήσεις demo και επαναφέρει τα αρχικά δεδομένα μετά από επιβεβαίωση.                                                                                                 |

Η επιλογή καταλύματος στην κορυφή εφαρμόζεται σε δείκτες, κριτικές και εργασίες.
Στη v0.3 η κάτω πλοήγηση περιλαμβάνει **Σήμερα, Κριτικές, Μοτίβα, Ενέργειες,
Προφίλ**. Η Δοκιμή κριτικής ανοίγει από το κουμπί **ΔΟΚΙΜΗ · 0.3** στην κορυφή.
Η οθόνη «Μοτίβα» διαθέτει παράθυρα 7, 14, 30 ή 60 ημερών και φίλτρο πηγής.
Το άνοιγμα θέματος δείχνει αποσπάσματα με πηγή και εξωτερικό ID, και από εκεί
ανοίγει η συγκεκριμένη κριτική ή φιλτράρεται το inbox.

Για τα μοτίβα, κάθε κριτική μετρά μία φορά ανά θέμα. Το ποσοστό αρνητικών
αναφορών έχει παρονομαστή τις κριτικές που αναφέρουν το συγκεκριμένο θέμα.
Η μεταβολή συγκρίνει αυτό το ποσοστό με το προηγούμενο ίσο χρονικό διάστημα,
σε ποσοστιαίες μονάδες. Όταν δεν υπάρχει συγκρίσιμο προηγούμενο δείγμα,
η μεταβολή παραμένει άγνωστη. Τα λυμένα περιστατικά παραμένουν στο ιστορικό.
Τα μοτίβα είναι ενδείξεις προς έλεγχο, όχι επιβεβαιωμένες συστημικές αιτίες.

Η αποθήκευση απάντησης ενημερώνει την ένδειξη «Χωρίς απάντηση». Η ολοκλήρωση
εργασίας δεν ισοδυναμεί με αποστολή απάντησης. Μια κριτική θεωρείται
ολοκληρωμένη όταν αντιμετωπιστούν όλες οι εντοπισμένες εκκρεμείς κατηγορίες της.

## Απαιτήσεις συστάσεων / πρόβλεψης

### Σύστημα συστάσεων: η βασική λειτουργικότητα της εργασίας

Οι `recommendations()` και `buildPlan()` αποτελούν ένα απλό **σύστημα συστάσεων
ενεργειών βάσει χαρακτηριστικών και περιορισμών**. Για κάθε εκκρεμές πρόβλημα:

1. Προσδιορίζονται κατηγορία, αρμόδιο τμήμα και πρότυπη διορθωτική ενέργεια.
2. Υπολογίζεται προτεραιότητα από βαρύτητα, επανάληψη της κατηγορίας στο ίδιο
   κατάλυμα τις τελευταίες 30 ημέρες και πρόσφατη εμφάνιση.
3. Χρησιμοποιούνται τα βάρη βαρύτητας/επανάληψης που δηλώνει ο χρήστης.
4. Επιλέγονται άπληστα έως τρεις προτάσεις που χωρούν **αθροιστικά** στον χρόνο
   και τον προϋπολογισμό του πλάνου.
5. Παραλείπονται ενέργειες που έχουν ήδη ανατεθεί, ακόμη και αν ολοκληρώθηκαν.
6. Η ανάθεση μπλοκάρεται μέχρι να επιβεβαιώσει ο χρήστης την ανάλυση της κριτικής.

Η άπληστη επιλογή δεν εγγυάται μαθηματικά βέλτιστο πλάνο. Το σκορ είναι
ευρετική προτεραιότητα, όχι πιθανότητα επιτυχίας. Το κόστος και ο χρόνος είναι
ενδεικτικές παραδοχές του demo, όχι εκτιμήσεις από δεδομένα αγοράς.

### Προσομοίωση ανάλυσης συναισθήματος

Η `analyze()` αναγνωρίζει λεξικές ενδείξεις, βασική άρνηση, κατηγορίες και
ορισμένες φράσεις επίλυσης ή υποθετικής επιθυμίας. Παρέχει ακριβή αποσπάσματα,
ετικέτες συναισθήματος και ενδεικτική εκτίμηση βαθμολογίας από το ήδη διαθέσιμο
κείμενο. **Δεν προβλέπει τη μελλοντική βαθμολογία ενός καταλύματος.**

- Η λειτουργία είναι προσομοίωση με κανόνες, όχι εκπαιδευμένο ML μοντέλο.
- Δεν υπάρχει σύνδεση με DistilBERT, DeBERTa, Qwen ή άλλο εξωτερικό pipeline.
- Δεν εμφανίζονται μη βαθμονομημένα ποσοστά βεβαιότητας ή ισχυρισμοί για άνοδο
  της βαθμολογίας μετά από μια παρέμβαση.
- Άγνωστο ή καθαρά πληροφοριακό κείμενο εμφανίζεται ως «Ανεπαρκείς ενδείξεις».
- Οι κανόνες έχουν περιορισμούς σε ειρωνεία, σύνθετη σύνταξη, πολλαπλές αρνήσεις,
  ανάμειξη κατηγοριών και μη αναγνωρίσιμο λεξιλόγιο. Απαιτείται ανθρώπινος έλεγχος.

Η κάλυψη των δοκιμαστικών περιπτώσεων δεν αποτελεί μέτρηση ακρίβειας NLP.

### Σύνδεση με το πραγματικό έργο NLP

Το backend παρέχει χωριστές λειτουργίες `/predict` για δυαδικό συναίσθημα,
`/absa` για επιμέρους θέματα και αποσπάσματα, και hotel-scoped recommendations.
Οι δημοσιευμένες τιμές **macro-F1 0.9642 και 0.9491** αφορούν τον ταξινομητή
συναισθήματος του backend σε συγκεκριμένα αγγλικά test sets. Δεν είναι
μετρήσεις του mobile mock, ακρίβεια ABSA ή βεβαιότητα κάθε πρόβλεψης.
Το `/triage` παραμένει πειραματικό και δεν καλείται από το mock.

Το σημερινό ABSA request δέχεται μόνο `language: "en"`. Τα ελληνικά παραδείγματα
του mock εκτελούνται τοπικά και δεν τεκμηριώνουν υποστήριξη ελληνικών από το API.
Οι έτοιμες περιπτώσεις της «Δοκιμής» είναι αγγλικές για να ταιριάζουν με αυτή
τη μελλοντική διασύνδεση. Δεν υπάρχει σήμερα ενεργή κλήση προς το backend.

Δες [API_INTEGRATION.md](API_INTEGRATION.md) για τα επιβεβαιωμένα API contracts,
τις αντιστοιχίσεις θεμάτων και όσα χρειάζονται επιπλέον backend υλοποίηση.

## Προτεινόμενο σενάριο επίδειξης — περίπου 3 λεπτά

Σε καθαρό browser ξεκινά ο οδηγός πρώτης χρήσης. Πέρασέ τον με «Επόμενο» ή πάτησε
«Παράλειψη».

1. Άνοιξε την αρχική και πάτησε «κριτικές υψηλής προτεραιότητας».
2. Άνοιξε μια κριτική και δες το απόσπασμα που στηρίζει την ενέργεια.
3. Πάτησε «Επιβεβαίωση ανάλυσης» και μετά «Έγκριση & ανάθεση».
   Δες το τμήμα και τη νέα κατάσταση.
4. Στις **Ενέργειες → Αναθέσεις**, ξεκίνησε και ολοκλήρωσε την εργασία.
5. Άνοιξε πάλι την κριτική, φτιάξε προσχέδιο απάντησης και αποθήκευσέ το στο demo.
6. Στη **Δοκιμή**, επίλεξε «Λυμένο» και «Επιθυμία»: δεν δημιουργείται νέα
   διορθωτική πρόταση ως πραγματικό εκκρεμές περιστατικό.
7. Στις **Ενέργειες → Προτάσεις**, άλλαξε χρόνο και προϋπολογισμό και δες το πλάνο.
8. Στα **Μοτίβα**, άνοιξε ένα θέμα, έλεγξε τα αποσπάσματα και δες τις σχετικές
   κριτικές με εμφανές φίλτρο θέματος.
9. Κάνε ανανέωση της σελίδας για να ελέγξεις τη διατήρηση των αλλαγών.

- **10 καταλύματα, 9 περιοχές και 39 συνθετικές κριτικές** κατά την επαναφορά.
- Οι 36 αρχικές κριτικές διατηρήθηκαν και προστέθηκαν 3 περιπτώσεις για τις ροές

- Οι εβδομάδες χωρίς κριτικές δεν αποκτούν επινοημένες βαθμολογίες.
- Δεν υπάρχουν analytics, cookies τρίτων, εξωτερικές γραμματοσειρές ή αιτήματα API.
- Οι ονομασίες των πηγών είναι metadata συνθετικών δειγμάτων. Δεν υπάρχουν
  συνδεδεμένοι λογαριασμοί, live συγχρονισμός ή επιβεβαιωμένες εμπορικές integrations.
- Η v0.3 διατηρεί το storage key `hostpulse.mock.v2` για να μη χαθούν οι υπάρχουσες
  απαντήσεις και αναθέσεις. Παλιές κριτικές αποκτούν σταθερά demo metadata πηγής.
- Η επαναφορά αφαιρεί τις τοπικές αλλαγές του demo. Υποστηρίζονται έως 200 κριτικές.
